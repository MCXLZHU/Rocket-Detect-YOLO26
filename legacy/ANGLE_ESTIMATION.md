# 第 3 步：ROI 内边缘检测 + 箭体倾角估计

**目标**：把第 2 步输出的稳定箭体框变成**逐帧倾角 φ(t)**，作为第 4 步姿态反算的输入。
**实现**：`scripts/rocket_angle.py`（核心模块 + 命令行）
**验证**：`scripts/validate_angle.py`、`scripts/test_angle_synth.py`、`scripts/_rot_test.py`
**产物**：`runs/angle/`（`angles.csv` / `angles.json` / `angle_timeline.png` / `angle_roi.mp4` / `validate.txt` / `synth.jpg`）
**状态**：✅ 已实现并验证。**合成图精度 0.03°；真实图像落地段重复性 σ=0.26°；旋转增益 0.90。**

---

## 一、需求确认

输入：视频帧 + 第 2 步的稳定框（`box`）与 ROI。
输出：每帧的
- `phi_deg` —— 箭体轴线**相对图像竖直**的带符号倾角（**正 = 顶端向右倾**）
- `phi_rel` —— 相对"落地竖直线"的相对倾角
- `w_body_px` —— 拟合出的条带宽度（第 4 步面外角反解要用）
- `conf` / `n_bands` / `rms_px` / `angle_ok` —— 质量门控

**不需要任何相机参数** —— 图像空间的倾角是纯几何量。

---

## 二、方案选型

| 方案 | 落地段 σ | 旋转增益 | 结论 |
|---|---|---|---|
| ROI 内 Otsu 二值化 + 最大连通域 + `minAreaRect` | 0.321° | **0.196** | ❌ 几乎不响应旋转 —— 低对比下二值化结果被背景主导，"稳定"是假象 |
| 逐行梯度峰 + 左右独立鲁棒直线拟合 | 0.304° | 0.712 | ⚠️ 可用，但增益只有 0.71（系统性低估 29%） |
| **分段行平均 + 先定条带再精修 + 中心线拟合** | **0.264°** | **0.898** | ✅ 采用 |

> 只看 σ 会选错方案：**"稳定"不等于"准确"**。一个对旋转不敏感的估计器同样能给出很小的 σ。
> 所以引入**旋转注入测试**作为准入门槛（见第五节）。

## 三、算法：为什么是这三步

箭体在画面里是**一根细长直筒**。这个物理事实给出两条强约束：左右两条轮廓边都是直线且**互相平行**；两边间距 = 筒身投影宽度（帧内近似恒定）。

```
ROI 裁剪(比框宽放宽 1.25×，因为成对边缘要留背景窗)
  ↓ 上采样 ×2~4 + 3×3 中值 + CLAHE
[1] 行分段           把行范围切成 16 段(每段 ~75 行)
  ↓
[2] 段内行平均       每段 ∂I/∂x 做行平均 → 噪声按 √行数 下降(≈8.7×)
  ↓
[3] 先定条带         1 维矩形脉冲匹配: S(x;w)=mean(I[x:x+w]) − 0.5·(左背景+右背景)
                     扫 8 档宽度(0.30~1.00 × 框宽) → 得到"左边缘大致位置 + 宽度"
  ↓
[4] 再精修           只在 [x±m]、[x+w±m] 两个窄窗里找梯度峰(m 由宽度档间距决定)
                     峰位用"超出半高部分的质心"(对平顶无偏)
  ↓
[5] 中心线拟合       xc=(xl+xr)/2 做 IRLS(Huber) 鲁棒直线拟合 → φ = atan(−斜率)
                     左右边各拟合一次只用于"不平行度"质量指标
  ↓
[6] 时序锁定         质量达标→锁定两条边；之后只在 ±5px 窄带内跟踪；失败则 hold
```

**为什么必须有 [3]（先定条带）**：不做的话，左边缘可能取自箭体、右边缘取自**支腿**，两者倾角不同 → 测出的轴线是"混合"结果。这是实测**旋转增益被压到 0.71** 的直接原因；加上 [3] 后回到 **0.90**。

**为什么必须有 [5]（中心线）**：中心线才是筒身轴线的无偏估计，而且左右边缘的随机误差在取中点时相互抵消。

**为什么必须有 [2]（段内行平均）**：落地段 ROI 里同时存在箭体/支腿/着陆坪/蒸汽带**多条近竖直强边缘**。逐行 argmax 会在它们之间乱跳，实测拟合残差高达 8~45 px，测出的倾角恒为 0（退化）。

## 四、关键代码

```python
# -*- coding: utf-8 -*-
import sys; sys.path.insert(0, "scripts")
import cv2
from rocket_track import RocketTracker, TrackerConfig, Det
from rocket_angle import AngleEstimator, AngleConfig, angle_roi, crop_roi

trk = RocketTracker(TrackerConfig(), bound_wh=(852, 480))
est = AngleEstimator(AngleConfig())

for i, raw in enumerate(dets_per_frame):        # raw: list[dict(c,s,x)]
    o = trk.step(i, [Det.from_dict(d) for d in raw], fps=30.0)
    if not (o.has and o.angle_ok and o.roi is not None):
        continue
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    # ★ 测角要用**放宽后**的 ROI: 跟踪器的 ROI 只比框宽 16%, 成对边缘没有背景窗
    p0, b0, org = crop_roi(gray, angle_roi(o.box, o.roi, cfg, W, H), o.box)
    r = est.step(p0, b0, org, i, o.reliability)
    if r.ok:
        print(i, r.phi_deg, r.phi_rel, r.w_body_px, r.conf)
```

核心两步（节选自 `band_edges`）：

```python
# [2] 段内行平均 —— 压噪声
prof  = (pol * np.gradient(patch, axis=1))[a:b].mean(axis=0)   # 梯度剖面
iprof = pol * patch[a:b].mean(axis=0)                          # 灰度剖面

# [3] 先定条带(1 维矩形脉冲匹配)
_sc, xb, wb = _bar_1d(iprof, lo, hi2, w_cands, cfg.bar_bg_ratio)
margin = max(4, int(round(0.70 * np.median(np.diff(w_cands)))))
wl = (xb - margin, xb + margin)
wr = (xb + wb - margin, xb + wb + margin)

# [4] 再精修 —— 峰质心(对平顶无偏)
se = prof[wl[0]:wl[1] + 1];  i = int(se.argmax())
xl = wl[0] + _peak_centroid(se, i, cfg.peak_half)

# [5] 中心线拟合
a, b, rms, m = _robust_line(ys, 0.5 * (xl + xr), cfg.irls_iters, cfg.inlier_k)
phi = np.degrees(np.arctan(-a))
```

## 五、验证方法（三层，缺一不可）

### 5.1 合成图单元测试 —— 把"实现是否正确"隔离出来

画一根**已知倾角**的亮条（90×1150 px，对比度 +60 灰阶，背景 2 灰阶噪声），检验链路能否还原：

| 真实倾角 | -5° | -3° | -2° | -1° | 0° | +1° | +2° | +3° | +5° |
|---|---|---|---|---|---|---|---|---|---|
| 测量 | -5.007 | -3.037 | -2.043 | -1.046 | -0.000 | +1.046 | +2.043 | +3.037 | +5.008 |

**增益 1.0088，线性残差 σ 0.024°，最大偏差 0.039°。**
抗干扰测试（旁边加一根更亮的斜条模拟支腿）：偏差 ±0.05°。

→ 结论：**估计器本身的几何与实现是正确的**，误差上限 0.04°。

### 5.2 旋转注入测试 —— 真实图像上的准入门槛

把真实 ROI 人为旋转 θ，测出的 φ 应当正好变化 θ。这是判断"测量是不是真的在测角度"的唯一硬指标。

> ⚠️ 测试本身有个坑：**框是轴对齐的**。目标倾斜 θ 后要仍然包住它，水平必须扩宽 `|tanθ|·h/2`
> —— 这正是真实场景里 YOLO 会给出的框。不同步扩宽，筒身两端会跑出搜索窗，测出的增益被
> 系统性压缩（实测 0.90 → 0.65）。**第一版测试就是这么错的**。

| 估计器 | 增益 | 偏置 | 线性残差σ |
|---|---|---|---|
| **本方案** | **0.898** | -0.229° | 0.187° |
| 逐行梯度峰 | 0.712 | +0.120° | 0.080° |
| Otsu+minAreaRect | 0.196 | -0.061° | 0.289° |

### 5.3 落地静止段重复性 —— 免费的"真值"

本视频 40s 后火箭已落地静止 ⇒ 真实倾角是常数。
**实测 46-66s 共 600 帧：φ 均值 -0.411°，σ = 0.264°，极差 1.381°，线性漂移 +0.008°/s。**

## 七、避坑指南（全部为本次实测踩到的真坑）

| # | 坑 | 现象 | 修法 |
|---|---|---|---|
| 1 | **逐行 argmax 会跳变** | 落地段 ROI 有箭体/支腿/着陆坪/蒸汽带多条近竖直边缘，逐行 argmax 在它们之间乱跳，拟合残差 8~45 px，φ 恒为 0（退化；旋转增益 = 0.000） | 改成**分段行平均**后再找峰：噪声按 √行数 下降，峰位由整段共同决定 |
| 2 | **平顶偏置** | 段内行平均把"倾斜直线"的梯度峰抹成**平顶**（宽度 = 斜率的函数），`argmax` 取平顶**第一个**位置 → 偏差与斜率成正比 → **增益被压到 0.76** | 峰位改用**"超出半高部分的质心"**（对平顶无偏） |
| 3 | **左右边缘取自不同结构** | 左边缘取自箭体、右边缘取自支腿 → 轴线是"混合"结果，**增益 0.71** | 加"**先定条带再精修**"：先用矩形脉冲匹配定出条带位置与宽度，再只在 ±m 窄窗里找边缘 |
| 4 | **ROI 太窄** | 跟踪器的 ROI 只比框宽 16%，成对边缘需要左右各留背景窗 → 可用宽度被卡死在 0.38×框宽，宽度扫描永远选到最窄档 | 测角单独用 `angle_roi()` 在水平方向放宽到 ±1.25×框宽 |
| 5 | **`Mw[s0:s1+1]` 被当成行切片** | numpy 里只写 `[a:b]` 是切**行**；本意是切列 → 形状不匹配 | 一律显式写 `[:, a:b]` |
| 6 | **MAD 尺度没有下限** | 拟合极好时（rms≈0.02 px）内点判据变得荒谬地紧（2.5×MAD≈0.04 px），把正常点全判成离群 → 合成图个别角度直接返回 None | `_robust_line` 加 `min_scale=0.15 px` 噪声下限 |
| 7 | **旋转注入测试本身要同步扩框** | 只旋转图像不扩框 → 目标两端跑出搜索窗 → **测出的增益被压缩**（会误判成算法缺陷） | 测试里同步把框按 `|tanθ|·h/2` 扩宽 |
| 8 | **框宽被支腿撑大** | 落地段框宽 35.3 px，而拟合筒身宽只有 18.3 px（比值 **0.52**） | 第 4 步反解面外角时 `w_body` **必须用拟合值，不能用框宽** |
| 9 | **低对比** | 落地段筒身 vs 扬尘的灰度差只有 **-26 灰阶**（下降段白筒 vs 蓝天则很强） | CLAHE 必须开：关掉后静止段 σ 从 0.264° 恶化到 **0.519°** |

## 八、交给第 4 步的接口与已知限制

### 8.1 可直接用

| 量 | 含义 | 可信度 |
|---|---|---|
| `phi_deg` | 轴线相对图像竖直的倾角 | 落地段 σ=0.26°；**旋转增益 0.90 ⇒ 存在约 ±10% 的尺度误差** |
| `phi_rel` | 减去落地基准（-0.417°）后的相对倾角 | 同上；假设"着陆时竖直 + 相机静止" |
| `w_body_px` | 拟合条带宽度 | 落地段 18.4±4.0 px。**注意可能抓到涂装条纹而非筒身轮廓**（见 8.3） |
| `conf` / `n_bands` / `rms_px` | 质量 | 建议下游再卡 `n_bands≥12 且 w_body≥8px` |

### 8.2 相机运动必须单独处理

相对倾角的前提是"相机在 t 与 t_land 之间无 pan/tilt"。7-40s 是**跟踪镜头**，必须做背景运动补偿
（用地面/着陆坪等静止特征估计相机滚转），否则相机运动会被误计为箭体倾斜。
40-69s 背景完全静止，落地基准可靠。

### 8.3 一个必须正视的限制

`w_body_px` 的物理含义是"**最显著的条带宽度**"，它可能是筒身轮廓，也可能是筒身上的涂装条纹
（实测 w_body/w_box 在 0.34~0.82 之间波动，σ=4.0 px）。第 4 步用它反解面外角前，
需要先用一个更明确的手段（如按行做全宽轮廓、或与已知 L/D 交叉校验）确认它对应的是筒身直径。

### 8.4 前 20s 的倾角不建议采信

11-15s 测出 +11.6°、15-20s +4.6°，但那段拟合出的条带宽度只有 **7~10 px**（箭体在 640 输入下只有
21×53 px），且估计值随目标变大而单调趋向 0 —— 这是**尺度相关的偏差**，不是真实姿态变化。
**可信区间从 ~25s 起**（w_body ≥ 12 px），最可信的是 45-69s。
