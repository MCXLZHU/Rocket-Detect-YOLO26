**踩坑记录（重要，后续务必遵守）**：
1. **conda 环境不能建在工作区内**。沙箱对工作区内批量删除有 50 文件阈值保护，pip/conda 替换大包时一次删上万文件 → 触发 `[SAFE_DELETE_BULK_REJECTED]` → 删除中途被打断 → 环境损坏（`Lib/*.py` 消失，报 `Could not find platform independent libraries`）。且 conda 用硬链接共享包缓存，会连带把 `E:\Anaconda\pkgs` 里的同名 inode 截断为 0 字节，污染包缓存。
2. **必须"只创建、不删除"**：先装 CUDA 版 torch，再装其余依赖。千万不要先装 PyPI 的 CPU 版 torch 再替换（卸载 torch 即触发上述问题）。PyPI 的 Windows torch 是 CPU 版（`torch.version.cuda` 为 None）。
3. `download.pytorch.org` 在本机网络被代理拦截(502)；改用 `mirrors.aliyun.com/pytorch-wheels`，且用 `scripts/fetch_wheels.py` 多线程下载（0.7MB/s → 4.8MB/s）。
4. 包缓存损坏的修复办法：用 `conda_package_handling.api.extract` 把包从 `.conda` 归档就地重新解压覆盖，无需删除。

## 补充（下午）

### 用户决策：保持 3 类训练，不改类别
- 用途：检测**可回收火箭落地过程**。虽然主要关心箭体，但降落过程中有一段"只有光点+尾焰"的时刻，
  提前定位火箭位置有价值；**后处理阶段再筛选箭体框**做后续工作。
- 因此放弃"合并单类/只留箭体"方案，`configs/rocket.yaml` 与训练逻辑保持不变。
- 已向用户说明：数据集中 3 类全部是火箭本身（尾焰/箭体/入轨光点），无无关目标。

### 关键技术结论（已实测验证）
- `single_cls=True` → 数据集 `cls[:]=0`，**框全保留**，trainer 里 `nc=1`、names={0:"item"}
- `classes=[...]` → 真删框（被删区域变背景），且 **nc 不变**（仍是 3）→ 方案B/C 必须重建派生数据集
- 训练速度与类别数几乎无关：检测头输出通道 `nc+4×reg_max`（3类→67，1类→65），该层占总 FLOPs <1%
- letterbox 实测（源图 640×360）：
  | 输入 | 输出 | 内容缩放 | 填充 | 像素量 |
  |---|---|---|---|---|
  | 正方形 640 | 640×640 | 1.0x | 43.8% | 410k |
  | 640x360 | 640×360 | 1.0x | **0%** | 230k |
  | 1280x720 | 1280×720 | **2.0x** | 0% | 922k |

### 修复：train.py 的 --imgsz 约定易写反
- 原实现按 "HxW" 解析，README 里写成 `640x384`/`1280x768` 会得到**竖版输入**（静默错误）

- 新增防呆：若解析出 `高>宽`（与数据集的横幅比例矛盾）在自检时打印醒目警告
- README 中 4 处错误写法已同步修正
- 已用 4 个用例验证解析与警告均正确
