## 不可推翻的结论
### 检测与训练
1. 100 轮/10.9h → mAP50 **0.928**、mAP50-95 0.569；**后 70 轮白跑**（ep30 已 0.5602），
   下次用 `--epochs 60 --patience 15`。`--imgsz` 只能正方形整数；`--cache` 收益≈0。
2. 数据集**有泄漏**（valid 66% 在 train 有近重复、19.6% 像素全同），无泄漏子集重测 0.914
   ⇒ 虚高仅 1.4 点，**0.928 可信**。
3. Space 类 mAP50-95 仅 0.339 是**物理下限**（框中位 7×9px），非训练不足。
4. **稳定化**：漏检根因是**单个 conf 兼任"建轨/续轨"** → 拆 conf_high 0.25 / conf_low 0.10。
   嵌套框 **IoS 中位 1.000 但 IoU 仅 0.64~0.70（卡在 NMS 阈值 0.7 之下，NMS 原理上抓不到）**
   → 类内 IoS 抑制 0.85，且**保留"更大的框"优于"分更高的框"**。
   框**下边沿双稳**（≈250/≈400px，最猛 +147px/帧）而上边沿 σ=0.46px
   ⇒ 状态量用 **ytop 而非中心 cy**。效果：缺帧 34→0、嵌套框 0 残留、开销 <1ms/帧。

### 测角（SAM 路线）
5. **原理**：箭体是回旋体，剪影左右边界中点连线 = 轴线投影；**不需要猜哪两条边属于同一根筒子**。
6. **精度**（两套分辨率都跑了全片）：
   | 指标 | 原方案 | SAM@512 | SAM@1024 |
   |---|---|---|---|
   | 旋转增益 | 0.898 | 0.963 | **0.975** |
   | 帧内残差 σ | 0.187° | 0.091° | 0.091° |
   | 测角有效帧 | 907 | 1730 | 1741 |
   512/1024 互拍 Δφ 中位 **+0.026°** ⇒ **512 已够用**。**帧内残差与分辨率无关**
   （由"逐行边界取中点的平均效应"决定）。
7. **原方案 w_body 口径确认是错的**：`w_body(SAM/原)` 中位 1.78 ⇒ 原方案量到的是**涂装条纹**；
   其条带相对剪影**倾斜 0.4~0.8°**（不是平行错开），这是两路线 Δφ=+0.76~0.82° 的根源。
   物理原因：**圆柱面上一条纵向母线在斜视角下的投影不平行于剪影边缘**。
8. **必须分块**（`--chunk 200`，OOM 自动减半）：1024² 每帧 12.6MB，全片 27.7GB ≫ 16GB。
9. **体检判据不能用 IoU，也不能用固定比例的 contain**：落地段框被支腿撑大；小目标段掩码
   越界 1~2px 就让 contain 掉到 0.74~0.81 ⇒ 实测 25 帧误杀 + 两个 200 帧块被整块截断。
   改用 `escape = 越界像素数 > max(3px, 0.35×框宽)`，且**连续 3 帧不过才重锚定**。
10. **旋转注入符号**：`cv2.getRotationMatrix2D` 正角=逆时针 ⇒ 理想增益是 **−1**（第一版写错过）。
11. **交叉验证统计口径**：必须**逐帧各自回归**再合并残差；多帧合并会把"帧间截距差"算进残差
    （σ 0.73 虚高 vs 真值 0.091）。

### 姿态与绘图
12. **完整 3D 姿态不可反算**（单视角 + L/D 未知）：换口径/L/D，β 从 0° 变到 60°+。
    可交付：φ(t)、90−|φ|、dφ/dt。
13. **φ 真实范围**本视频 ∈ [−1.97, +15.94]（早期 7-15s 挂在 +12~+15°）。
    **绘图纵轴绝不能固定 ±8°**（会截掉 10.93% 的帧）——用户拿量角器量出 13° 才发现。
14. **取轴原则**：φ 轴按数据 auto 且**不强制对称**；差异量（Δφ 之类）必须按**稳健分位**
    （p96×1.25）而不是 max。截顶帧数要打印出来，不静默丢失。
15. **画曲线图**：图区内**没有安全位置放图例** ⇒ 说明文字一律放图外页脚，图区顶部单开标注行。
    dφ/dt 必须用**窗内中心差分**（±5 帧），直接画 CSV 的 `dphi_dt` 全是噪声。
16. **横轴按数据自适应**（`sam_angle_viz.data_window`）：有效帧跨度 < 全片 60% 时把横轴缩到
    数据窗口，否则曲线被压扁（原视频占 94% 不受影响）。

## 泛化能力（2026-10-08 起，用户明确要求）
17. **代码里不留任何"只对本视频成立"的先验**。要点：
    * 交付量是**绝对角** φ(t) = 轴线 vs 图像竖直（纯几何量）——**不做 φ_rel**
      （它需要"片尾落地即竖直"的先验，**用户明确不要**）。CSV 里 `phi_rel` 列保留但恒空。
    * 无写死时间窗/帧号/尺寸：可信起点由 `sam_angle_viz.reliable_from()` 判（筒身宽首次稳定
      达到**片尾中位宽×0.6**，本视频 19.7s）；相机配准参考帧取有效区间 50% 分位；
      像素门限按 `k=min(W,H)/480`（tracker/seg）或当帧剪影尺寸（mask 角度）自适应，**只放宽不收紧**。
    * 视频可放**项目外**（`scripts/video_io.py`：`resolve_video/video_field/pick_video/probe_video`），
      meta 用 `video_path`。
    * ⚠️ **帧缓存目录必须带视频标识**（`video_io.video_key` = 路径+大小+分辨率+帧数的哈希）：
      原来只按帧号区间命名，换视频会静默复用上一个视频的帧（实测 360p 拿 480p 老帧 → IndexError）。
    * ⚠️ **`--det-imgsz` / `--sam-imgsz` 默认 auto**（`video_io.auto_imgsz`）：按"长边→网络输入"
      保持参考配置 852×480→640/512 的比例，夹到 [640,1280] / [512,1024]。
      **高分辨率视频继续用 640 会把目标缩没**（见 §18）。852×480 结果与历史**完全一致**。
    * ⚠️ **标签冲突护栏**（`pipeline._auto_suffix`）：默认标签只跟参数走（`iou70`/`s512`），
      换视频直接跑会**静默覆盖上一支视频的产物**。现仅当同名产物确实属于别的视频时，
      才给未显式指定的标签加视频名后缀。
    * 换视频最可能卡在**检测器不认识新火箭** —— 先看 `runs/diag/analysis.txt`，必要时换权重/微调。

18. **跨视频实测（changzheng1.mp4，1916×1080/30fps/1308帧）**：
    * **检测瓶颈是 imgsz 不是遮挡**：箭体在画面里只占 30~50px（**1.6% 画幅宽**），
      `imgsz=640` 下缩到 10px → 分数掉到 0.02，12s 后全丢；`imgsz=1280` → 0.33~0.42，覆盖到 18s。
      另外 640 时 9-12s 那些 123~146px 的"箭体框"其实是**把烟柱当箭体**，1280 才回到合理的 30~50px。
    * **可用区间 0.4~15s（467 帧被追踪）**，测角有效 166~205 帧（12.7~15.7%）；
      15s 后火箭进入塔架**被结构遮挡**（用户已知，说"暂时先保留"）。
    * 结果：φ ∈ [−10.25, +5.65]，中位 +0.87°；分段 0-4s −9.7°、4-7s +2.4°、7-11s +4.4°、11-14s +0.4°。
      掩码贴得准（见 `runs/sam/stills_zoom_s1024_changzheng1.png`）。
    * ⚠️ **相机核查要当心**：背景配准给出滚转 σ 1.17°（原视频只有 0.06°），但这支片子海面/烟云
      **自身在动**，且**地平线太朦胧无法作为独立基准**（单像素梯度、上下窗匹配两种方法都撑不起来）。
      一次勉强可用的地平线拟合显示倾角变化 ≤ ±0.7° ⇒ **配准那 1.2° 多半含场景运动**。
      ⇒ 这类"大背景在动 + 无清晰地平线"的片子，φ 的不确定度应估 ~1°，别把配准值当真滚转。

## 一键流水线
`python pipeline.py --video <路径> --tag <检测标签>` →
detect(GPU) → stabilize → **seg(GPU)** → angle_mask → attitude。
阶段可缓存（产物存在即跳过，`--force` 强制重跑）；`--summary/--list/--only/--from/--to`。
**没有 `--sam` 开关**（SAM 是唯一主线）。日志 `runs/pipeline_log.txt`。
本机实测：原视频 852×480 全链路 467s（含 detect@640 与 seg@1024 重跑）；新视频 1916×1080
detect@1280 仅 28.7s、seg@1024 84.9s。

## 命令与工具的硬限制
- ⚠️ **批量删除阈值是硬性 50 个文件**：>50 被 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` **整条作废**
  （命令不执行），普通/重试/`dangerouslyDisableSandbox` 三条路都过不去。⇒ 脚本坚持"只写不删"。
- **长任务**：前台 + 显式 `timeout`（实测 1500s 的 Bash 调用可正常跑完）；分段跑更稳。
- ⚠️ **`cv2.putText` 只支持 ASCII**：中文会变乱码方块**并与相邻文字重叠**。中文走 PIL
  （微软雅黑 `C:\Windows\Fonts\msyh.ttc`）。
- ⚠️ **不要在 PowerShell 里内联 `python -c "..."` 写复杂脚本**（`\"` 不是 PS 转义，会截断）
  ⇒ 一律写成 `.py` 文件再跑。Bash 工具在本机**可用**（Git Bash），内联 python 也有引号风险，同样写文件。
- `csv` 模块会把 `True/False` 写成字符串 ⇒ 下游按 `"1"` 解析全读成 0，写布尔必须显式 `int(v)`。
- 判空坑：`if x:` 对 **0.0** 判假（可信起点 0.0 被误报 "n/a"）⇒ 用 `is not None`；
  `arr[...] or arr` 对 numpy 数组抛 ambiguous truth value。
