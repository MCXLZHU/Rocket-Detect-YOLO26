## 命令 120 秒上限（本轮，重要）
- 1024 全片跑了两次都在 **2 分 01 秒**断掉、退出码 1；而**单独重跑那一块只要 30s 就通过**。
  ⇒ 真因**不是内存累积**（我一开始判断错了，已在代码注释里更正），而是
  **后台任务被 120s 上限杀掉**。512 全片用了 1 分 55 秒，恰好躲过，所以之前没暴露。
- 对策：长任务用**前台 + 显式 `timeout`（最长 600000ms = 10 分钟）**，
  或按 `--start/--end` 切成每段 < 2 分钟的多条命令（块目录按区间命名，天然可续跑）。
- 代码里保留的 `gc.collect()` 是防御性动作，不是已证实的泄漏修法。

3. **凭据类命令会被沙箱整体拦截**：`git credential fill` / `git credential-manager` 组合命令
   表现为「命令不执行、连第一个 `Out-File` 都不落盘、退出码 1」。
   凡是遇到"命令零副作用"的现象，先怀疑沙箱策略拦截，而不是脚本写错。
4. git 出网走沙箱代理 `127.0.0.1:8860`（`GIT_CURL_VERBOSE=1` 可见 CONNECT 隧道）。
   **`git ls-remote`（读）匿名可用；`git push`（写）必须认证。**
5. `git credential-manager github list` 只反映"已登记账号"，**不代表 token 可用**（登录可能 exit=1）。
6. 结论：**推送必须在沙箱外执行**（`dangerouslyDisableSandbox`），且需要用户完成浏览器授权。
