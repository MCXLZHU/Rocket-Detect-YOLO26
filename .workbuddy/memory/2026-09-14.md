### 关键实测结论（勿凭直觉推翻）
1. **"漏检 264 帧"是误读**：其中 **228 帧是 0–7.6s 高空段**，火箭只是光点，模型正确判为 Space。
   真实漏检只有 **34 帧**，集中在 t=8.4–9.6s（10 帧）与 **t=38.2–39.6s（23 帧）**。
   且这些帧里 **RB 框并没有消失**，只是掉到 0.085~0.250 —— 根因是 **单一 conf 同时承担"建轨"和"续轨"两种职责**。
   → **conf_high=0.25 建轨 / conf_low=0.10 续轨**，一次覆盖 33/34 帧。降全局 conf 不行：重复框会从 47 帧涨到 115 帧。
2. **嵌套框 47 帧，IoS 中位 1.000（完全包含）、IoU 仅 0.643~0.699**
   → 恰好卡在 ultralytics 默认 NMS 阈值 0.7 之下，**NMS 原理上抓不到嵌套框**。
   把 iou 降到 0.3 也能清零（实测），但更可控的是加类内 IoS 抑制规则。
   **保留"更大的框"优于"分更高的框"**（模式切换 2 vs 6 帧、|Δy2|max 27 vs 57、ROI 漏裁 0 vs 7）。
3. **框下边沿 y2 是"双稳"的**（≈250px / ≈400px 两个聚集，9 次单帧 |Δy2|>30px 跳变，最猛一次 +147px），
   而**上边沿 y1 同时段始终 49~56px（σ=0.46px）**。
   → 状态量必须用 **ytop** 而不是中心 cy；高度交给"持续性门控的模式状态机"（tol 22%/3px、persist 3）。
   **反例教训**：按常规"检测到跳变就放大 R"会让滤波器在两模式间取平均，帧 1160–1170 的 y1 漂到 224（真值 50）。
4. **烟尘无实质影响**：落地静止段（42–68s）框高 333±3.5px、σ(y1)=0.46px、置信度中位 0.57~0.78，**无收缩无丢失**。
   唯一伤害窗口是 38.2–39.6s（高亮蒸汽带把框切成上下两半）。**用户"先不动去雾"的决定有数据支持**。
5. **本视频 40s 后火箭已落地静止**，倾角退化为常数；**真正携带姿态信息的是 11–40s**。
   7–11s 箭体框仅 9×20px，**倾角物理上不可估**。
6. **L3 伪3D姿态的坑**：落地段框 35×333px（h/w≈9.5），而朱雀3号真实 L/D≈17，差一倍。
   最可能是**框宽由展开支腿决定而非筒径**（333/17≈19.6px 才是筒径量级）。
   ⇒ 反解面外角时 **w_body 必须来自边缘检测量筒身两侧轮廓间距，不能用框宽**。

## 任务三：第 3 步 ROI 内边缘检测 + 倾角（2026-09-15）

用户要求实现"提取箭体长边边缘、计算倾角"。先做诊断→实现→三层验证→迭代到收敛。

### 产出

- `scripts/test_angle_synth.py`（合成图单元测试）、`validate_angle.py`（三层验证）、
  `_rot_test.py`（快速旋转注入）、`angle_report.py`（时间线图）、`debug_angle*.py`、`_score_map.py`
- 产物：`runs/angle/`（angles.csv/json、angle_timeline.png、angle_roi.mp4、validate.txt、synth.jpg）

### 最终算法（三重约束，缺一不可）
ROI 放宽到 ±1.25×框宽 → 上采样×2~4 + 3×3中值 + CLAHE
→ [1] 行分 16 段 → [2] 段内 ∂I/∂x 行平均（压噪 √n）
→ [3] **先定条带**（1 维矩形脉冲匹配，8 档宽度）→ [4] **再精修**（两个窄窗内找梯度峰，
峰位用"超出半高部分的**质心**"）→ [5] **中心线**（xl+xr)/2 做 IRLS 鲁棒拟合
→ [6] 时序锁定 + ±5px 窄带跟踪。

### 验证结果（三层）
1. **合成图单元测试**（已知倾角亮条）：增益 **1.0088**，线性残差 σ **0.024°**，9/9 全对；
   旁边加更亮的斜条模拟支腿 → 偏差 ±0.05°。**证明实现本身正确。**
2. **旋转注入（真实 ROI）**：增益 **0.898**，线性残差 σ 0.187°。
   对比：逐行梯度峰 0.712、Otsu+minAreaRect **0.196**。
   → **只看 σ 会选错方案**（朴素法落地段 σ=0.321 但旋转增益只有 0.196，"稳定"是假象）。
3. **落地静止段重复性**（46-66s 真值为常数）：600 帧，σ **0.264°**，极差 1.38°，漂移 +0.008°/s。

吞吐 60 fps（纯测角，不含 YOLO），2203 帧 36.6s。

### 六个关键坑（全部实测踩到，已在文档中列表）
1. **逐行 argmax 会跳变**：落地段 ROI 有箭体/支腿/着陆坪/蒸汽带多条近竖直边缘，
   拟合残差 8~45px，φ 恒为 0（旋转增益 0.000，完全退化）→ 改分段行平均。
2. **平顶偏置**：段内行平均把倾斜边缘的梯度峰抹成平顶，argmax 取第一个位置
   → 偏差与斜率成正比 → 增益压到 0.76 → 改用**峰质心**。
3. **左右边缘取自不同结构**（左取箭体、右取支腿）→ 增益 0.71
   → 加"先定条带再精修"→ 提到 0.90。
4. **ROI 太窄**：跟踪器 ROI 只比框宽 16%，成对边缘没背景窗 → 宽度扫描被卡死在 0.38×框宽。
5. **`Mw[s0:s1+1]` 被 numpy 当成行切片**（本意切列）→ 形状不匹配。
6. **MAD 尺度无下限**：拟合极好时内点判据过紧把正常点判成离群 → 加 `min_scale=0.15px`。
7. **旋转注入测试本身要同步扩框**（`|tanθ|·h/2`），否则增益被假性压缩（0.90→0.65），
   会误判成算法缺陷。
8. **框宽被支腿撑大**：落地段框 35.3px 而拟合筒身仅 18.3px（比值 0.52）。
9. **低对比**：落地段筒身 vs 扬尘仅 -26 灰阶；关掉 CLAHE 后 σ 从 0.264 恶化到 0.519。

### 给第 4 步的接口与限制
- 输出 `phi_deg`（相对图像竖直，正=顶端右倾）、`phi_rel`、`w_body_px`、`conf`。
  落地段 φ 均值 **-0.411°**，即火箭在图像里基本竖直。σ=0.26°。
- **旋转增益 0.90 ⇒ 存在约 ±10% 的尺度误差**，绝对倾角要打这个折。
- 相对倾角前提"相机静止"：7-40s 是跟踪镜头，**必须做背景运动补偿**。
- `w_body_px` 可能是涂装条纹而非筒身轮廓（w_body/w_box 在 0.34~0.82 波动，σ=4.0px），
  第 4 步反解面外角前必须先确认它对应筒身直径。
- **前 20s 的倾角不可采信**（那段条带只有 7~10px，且估计值随目标变大单调趋向 0，
  是尺度相关偏差而非真实姿态）。可信区间从 ~25s 起，最可信是 45-69s。

### 结论：夹角可行，完整 3D 姿态不可反算
**可行**：箭体与图像竖直的夹角 φ(t)、与图像上边缘的夹角 90−|φ|、相对倾角 φ−φ_ref、角速率 dφ/dt。
**不可行**：面外角 β 与总倾角。

### 关键实测（含两个方法论坑）
1. **相机基本静止**（直接对参考帧配准）：落地段滚转 +0.03°±0.06°（max 0.13°）⇒ φ_ref 可靠；
   下降段 σ≈0.31° ⇒ 该段应减 cam_roll(t)。
   **必须做灵敏度校验**：注入 0.25/0.5/1.0° → 测得完全一致，增益 1.000。
   否则"测得静止"可能只是估计器不敏感（与第 3 步"稳定≠准确"同一个陷阱）。
2. **相机滚转不能逐帧累加**：单帧误差 σ≈0.018°，2202 帧随机游走累出 **6° 假漂移**。第一版就是这么错的，
   改成每帧直接对参考帧配准才正确。
3. **本视频没有地平线**（8 帧全检不出近似水平长直线）⇒ 只能用"落地竖直"当基准。
4. **β 灵敏度**：落地段 沿轴 271.1px / 拟合筒身宽 18.3px / 框宽 35.3px（比值 1.93）。
   换口径或换 L/D ⇒ **β 从 0° 到 67°**；cosβ_raw=1.06>1 几何不自洽。
5. **用"落地必竖直"标定出 L/D=14.52**，但用到下降段后 β 在 **0°~60°** 摆动（物理不可能）
   ⇒ **反证 w_body 各阶段量到不同结构**（占框宽 0.34~0.82 波动）。**用失败的标定作反证**是关键论证。
6. **透视项**：≈atan(|x−x_c|·tanθ_pitch/f)。落地段横向偏 8.5px ⇒ <0.45°（典型 0.11°）基准不受影响；
   下降段偏 100px ⇒ 最坏 5.2° ⇒ 下降段绝对倾角不可采信。

### 结果
落地段 90−|φ|=89.63°、相对倾角 +0.05°、σ=0.26° ⇒ 火箭在图像里基本竖直。
下降段 φ 从 +11.6° 降到 −2.5°，绝对量不可采信，可用的是趋势与角速率（−7°/s → −3°/s）。

### 要真正做 3D 姿态需补（按性价比）
① 分割出筒身轮廓（顺便修好 w_body 抖动）② 真实 L/D 或三维模型 → 剪影匹配 ③ 相机内参+俯仰 ④ 多视角。
